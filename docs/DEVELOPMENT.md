# Tunnel Browser — для разработчиков

Пользовательская инструкция — в [README](../README.md). Здесь всё остальное: как устроена защита,
как собрать проект и как выпускать версии.

## Как устроена защита

Браузер открывается только после того, как туннель проверен настоящим запросом через сервер.
Дальше трафик держат три независимых слоя ([tunnelSession.ts](../src/main/tunnelSession.ts)):

1. **Единственный маршрут.** Сессия браузера настроена на один прокси: локальный вход Xray
   (`127.0.0.1`, случайный порт, одноразовые логин и пароль). Прямого выхода (`DIRECT`) нет.
   Когда туннель выключен, прокси указывает на «чёрную дыру» — порт, который держит само
   приложение, так что его не может занять чужая программа. После каждой смены прокси
   приложение сверяет `resolveProxy`: если Chromium применил не то, браузер не разблокируется.
2. **Проверка каждого запроса** (`webRequest.onBeforeRequest`). Пока туннель не подтверждён,
   любой сетевой запрос отменяется. Адреса этого компьютера и локальной сети запрещены всегда,
   плюс их же блокирует маршрутизация в самом Xray.
3. **Интерфейс.** Без туннеля страницы отсоединены от окна, адресная строка отключена.
   Если ядро упало, блокировка срабатывает раньше всего остального. При отключении и
   переподключении интерфейс блокируется в том же такте, что и проверка запросов, ещё до
   смены прокси и остановки ядра.

Состояние туннеля хранится в одном месте — [tunnel.ts](../src/main/tunnel.ts); вкладки и
интерфейс только следуют за ним. Пока туннель подключён, он проверяется так:

- раз в 10 секунд — запрос через сервер (`generate_204` у Google и Cloudflare одновременно,
  таймаут 5 с);
- сразу же, если страница получила то, что даёт мёртвый сервер: пустой `503` без заголовка
  `Date` (так HTTP-вход Xray отвечает на обычный `http`, когда не может достучаться до сервера)
  или обрыв соединения для `https` ([guard.ts](../src/main/guard.ts)). Это только повод
  проверить: решает собственная проверка;
- две неудачи подряд — состояние `degraded`: «Туннель недоступен», жёлтая полоса, вкладки
  скрыты. Проверка запросов остаётся открытой, утечь всё равно некуда: единственный маршрут —
  Xray, который не достаёт до сервера. Проверка идёт каждые 3 с, и при первом успехе вкладки
  возвращаются сами, а страницы, не загрузившиеся без связи, перезагружаются.

А также:
- WebRTC: политика `disable_non_proxied_udp` (самопроверка: 0 UDP-кандидатов против 3 без защиты);
- геолокация, камера, микрофон, USB/HID/Serial запрещены; открываются только `http(s)`;
- User-Agent как у обычного Chrome, без `Electron/…`;
- серверы, закладки и сеанс зашифрованы через `safeStorage` (DPAPI / Keychain). Отказ хранилища
  ключей не считается повреждением: файл не трогается, запись блокируется
  ([encryptedFile.ts](../src/main/encryptedFile.ts));
- ядро Xray скачивается только с GitHub XTLS и сверяется с SHA-256, закреплённым в
  [fetch-xray.mjs](../scripts/fetch-xray.mjs); конфиг передаётся через stdin и на диск не пишется;
- Electron fuses: `runAsNode` выключен, проверка целостности ASAR, только `app.asar`, шифрование куки;
- интерфейс (default session) не ходит в сеть вообще, значки сайтов не загружаются.

## Разработка

Нужен Node.js 24.

```bash
npm ci
npm run fetch-xray     # ядро Xray для этой платформы, со сверкой SHA-256
npm run dev            # собрать и запустить
npm test               # юнит-тесты + настоящие туннели через локальный сервер Xray
npm run smoke          # самопроверка kill-switch в Electron на живом туннеле
npm run dist:win       # установщик Windows в dist/ (можно собирать и на macOS)
npm run dist:mac       # DMG и ZIP для Apple Silicon и Intel (только на macOS)
```

`npm run smoke` поднимает локальный сервер Xray (VLESS + Reality), запускает приложение в режиме
самопроверки и проверяет изнутри: блокировку без туннеля, выход через сервер, недоступность
localhost и локальной сети, WebRTC, падение ядра, работу без проверки запросов, восстановление
вкладок и закладки. Скриншоты кладёт рядом с `results.json`. Этот код в релизную сборку не попадает.

Обновить Xray: поменять `XRAY_VERSION` и хэши в `scripts/fetch-xray.mjs` (значения `SHA2-256`
из файлов `*.zip.dgst` релиза XTLS/Xray-core).

## Версии и обновления

Каждая версия — тег `vX.Y.Z` и релиз на GitHub с установщиками для Windows и macOS. Приложение
проверяет релизы при запуске и раз в 6 часов ([updater.ts](../src/main/updater.ts)).

- **Windows:** electron-updater + NSIS, установка без прав администратора. Перед установкой
  туннель закрывается, установщик дополнительно завершает `tunnel-browser-core.exe`.
- **macOS:** Squirrel.Mac принимает только подпись Developer ID, поэтому неподписанная сборка
  обновляет себя сама ([macUpdate.ts](../src/main/macUpdate.ts)): ZIP для своего процессора →
  SHA-512 из `latest-mac.yml` → проверка идентификатора, версии и `codesign --verify --deep
  --strict` → после выхода подмена пакета (старый удаляется только когда новый на месте) → запуск.
  Нужна запись в папку приложения, поэтому при первом запуске оно предлагает переместиться
  в «Программы».

### Как выпустить версию

1. Опишите изменения в [CHANGELOG.md](../CHANGELOG.md), в разделе «Не выпущено».
   Этот текст попадёт в описание релиза и в окно обновления у пользователей.
2. Выполните:
   ```bash
   npm run release -- patch      # или minor / major / 1.2.0
   ```
   Скрипт переносит раздел под новую версию, поднимает версию в `package.json`
   и `package-lock.json` и делает коммит `release: vX.Y.Z`.
3. Нажмите **Push origin** в GitHub Desktop.
4. [release.yml](../.github/workflows/release.yml) видит версию без релиза: ставит тег, создаёт
   черновик, на Windows и macOS параллельно прогоняет тесты и собирает установщики, проверяет,
   что все 8 файлов на месте, публикует релиз и убеждается, что обе ленты обновлений
   (`latest.yml`, `latest-mac.yml`) отдают новую версию. Это 10–15 минут.
   Если сборка упала, после исправления достаточно снова запушить (или Actions → Release →
   Run workflow): уже выпущенные версии пропускаются.

### Требования к репозиторию

- Репозиторий с релизами должен быть **публичным**: приложение скачивает обновления без токена.
  Код можно держать закрытым, а релизы публиковать в отдельный публичный репозиторий
  (`publish.repo` в `electron-builder.yml`).
- В `package.json` указано поле `repository`: по нему сборка понимает, откуда брать обновления.

## Что дальше

- **Подпись для Windows** (сертификат или Azure Trusted Signing) — уберёт предупреждение SmartScreen.
- **Apple Developer ID и нотаризация** ($99 в год) — уберут предупреждение Gatekeeper и запрос
  связки ключей после обновлений. В `electron-builder.yml`: убрать `identity: '-'`, включить
  `hardenedRuntime` и нотаризацию; обновления можно будет вернуть на Squirrel.Mac.
- **Защита отдельных приложений**: Windows — служба + Xray TUN с маршрутизацией по процессам +
  постоянные правила брандмауэра WFP; macOS — системное сетевое расширение (нужен Developer ID).
- Потом: Linux, Android (WebView + `ProxyController` + libXray), iOS (WKWebView +
  `proxyConfigurations`, iOS 17+).

## Устройство проекта

```
src/main/          основной процесс Electron
  tunnel.ts          жизненный цикл туннеля: запуск → проверка → открыть браузер
  tunnelSession.ts   kill-switch: прокси, «чёрная дыра», проверка запросов, разрешения
  guard.ts           чистые проверки адресов (localhost/LAN, схемы)
  xray.ts            запуск ядра Xray
  xrayConfig.ts      генерация конфига Xray
  links.ts           разбор ссылок vless/vmess/trojan/ss и подписок
  subscription.ts    загрузка подписок
  health.ts          проверка туннеля и IP выхода
  tabs.ts            вкладки, восстановление, закрытые вкладки, всплывающие окна
  bookmarks.ts       чистые функции закладок
  browserData.ts     закладки, настройки и сеанс
  store.ts           серверы и подписки
  encryptedFile.ts   зашифрованные файлы данных
  updater.ts         обновления из GitHub Releases, история версий
  macUpdate.ts       самообновление macOS-сборки без Developer ID
src/preload/       мост между интерфейсом и основным процессом
src/renderer/      интерфейс на React
scripts/           сборка, скачивание Xray, выпуск версии, самопроверка
tests/             тесты (включая настоящий Xray)
```
