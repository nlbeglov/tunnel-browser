# Tunnel Browser

Браузер на Chromium, который **физически не может выйти в интернет мимо VPN-туннеля** (Xray).
Нет туннеля — у браузера нет сети вообще. Остальные программы на компьютере работают напрямую,
системный VPN не нужен.

Сейчас: **Windows** (x64). Дальше: macOS, потом остальные платформы.

## Как устроена защита

Браузер открывается только после того, как туннель проверен настоящим запросом через сервер.
Дальше трафик держат три независимых слоя:

1. **Единственный маршрут.** Сессия браузера настроена на один прокси: локальный вход Xray
   (`127.0.0.1`, случайный порт, одноразовые логин и пароль). Прямого выхода (`DIRECT`) нет.
   Когда туннель выключен, прокси указывает на «чёрную дыру» — порт, который держит само
   приложение, так что его не может занять чужая программа.
2. **Проверка каждого запроса.** Пока туннель не подтверждён, любой сетевой запрос отменяется.
   Адреса этого компьютера и локальной сети (`localhost`, `192.168.x.x`, `10.x.x.x`…) запрещены
   всегда, плюс их же блокирует маршрутизация в самом Xray.
3. **Интерфейс.** Без туннеля страницы скрыты, адресная строка отключена. Если ядро упало,
   блокировка срабатывает раньше всего остального.

А также:
- WebRTC не может слать UDP мимо туннеля (проверяется тестом: 0 кандидатов против 3 без защиты);
- геолокация, камера, микрофон, USB/HID/Serial запрещены;
- открываются только `http(s)`, никаких `file://` и внешних протоколов;
- User-Agent как у обычного Chrome, без `Electron/…`;
- серверы хранятся зашифрованными средствами ОС (DPAPI в Windows, Keychain в macOS);
- ядро Xray скачивается только с официального GitHub и сверяется с SHA-256, закреплённым в репозитории;
- флаги Electron (fuses): нельзя запустить как Node, нельзя подменить код (проверка целостности ASAR),
  куки зашифрованы.

`npm run smoke` проверяет всё это в настоящем приложении на живом туннеле (см. ниже).

## Поддерживаемые ссылки

VLESS (Reality, TLS, Vision, WS, gRPC, XHTTP, HTTPUpgrade, mKCP), VMess, Trojan, Shadowsocks
(включая 2022), подписки (base64 или текст, заголовки `profile-title`, `subscription-userinfo`,
`profile-update-interval`).

Намеренно **не** импортируются: `allowInsecure=1` без закреплённого сертификата (Xray это убрал:
открывает дорогу MITM), VLESS без шифрования на публичный адрес, плагины Shadowsocks.
Пока не поддерживаются: Hysteria2, TUIC, WireGuard.

## Разработка

Нужен Node.js 24.

```bash
npm ci
npm run fetch-xray     # ядро Xray для этой платформы, со сверкой SHA-256
npm run dev            # собрать и запустить
npm test               # юнит-тесты + настоящие туннели через локальный сервер Xray
npm run smoke          # самопроверка kill-switch в Electron на живом туннеле
npm run dist:win       # собрать установщик Windows в dist/ (можно и на macOS)
```

## Версии и обновления

Каждая версия — это тег `vX.Y.Z` и релиз на GitHub с установщиком и описанием изменений.
Установленное приложение проверяет релизы при запуске и раз в 6 часов. Если вышла новая версия,
появляется кнопка **«Обновить»**: она скачивает обновление (с проверкой SHA-512), закрывает туннель,
ставит новую версию без прав администратора и перезапускает приложение. Вся история версий
видна в настройках приложения и на странице Releases.

### Как выпустить версию

1. Опишите изменения в `CHANGELOG.md`, в разделе «Не выпущено».
2. Выполните:
   ```bash
   npm run release -- patch      # или minor / major / 1.2.0
   ```
   Скрипт переносит раздел под новую версию, поднимает версию в `package.json` и делает коммит
   `release: vX.Y.Z`.
3. Нажмите **Push origin** в GitHub Desktop.
4. GitHub Actions (`.github/workflows/release.yml`) видит версию, для которой ещё нет релиза:
   прогоняет тесты на Windows, ставит на коммит тег `vX.Y.Z`, собирает установщик и публикует
   релиз. Через несколько минут у пользователей появится кнопка «Обновить».
   Если сборка упала, после исправления достаточно снова запушить (или Actions → Release →
   Run workflow): уже выпущенные версии пропускаются.

### Требования к репозиторию

- Репозиторий с релизами должен быть **публичным**: приложение скачивает обновления без токена.
  Если код нужно держать закрытым, релизы можно публиковать в отдельный публичный репозиторий
  (`publish.repo` в `electron-builder.yml`).
- В `package.json` должно быть поле `repository` (или `git remote origin` на GitHub): по нему
  сборка понимает, откуда брать обновления.

## Что дальше

- **Подпись для Windows.** Пока установщик не подписан, SmartScreen показывает предупреждение
  при первой установке. Автообновления работают и так. Подпись: сертификат или Azure Trusted Signing.
- **macOS.** Сборка уже настроена (`dmg` + `zip`, arm64 и x64), но для автообновлений нужна подпись
  и нотаризация Apple (Apple Developer ID, $99 в год).
- Потом: Linux, Android (WebView + `ProxyController` + libXray), iOS (WKWebView +
  `proxyConfigurations`, iOS 17+).

## Устройство проекта

```
src/main/        основной процесс Electron
  tunnel.ts        жизненный цикл туннеля: запуск → проверка → открыть браузер
  tunnelSession.ts kill-switch: прокси, «чёрная дыра», проверка запросов, разрешения
  guard.ts         чистые проверки адресов (localhost/LAN, схемы)
  xray.ts          запуск ядра Xray (конфиг через stdin, на диск не пишется)
  xrayConfig.ts    генерация конфига Xray
  links.ts         разбор ссылок vless/vmess/trojan/ss и подписок
  health.ts        проверка туннеля и IP выхода
  tabs.ts          вкладки (WebContentsView), всплывающие окна
  updater.ts       обновления из GitHub Releases, история версий
  store.ts         зашифрованное хранилище серверов
src/preload/     мост между интерфейсом и основным процессом
src/renderer/    интерфейс на React
scripts/         сборка, скачивание Xray, выпуск версии, самопроверка
tests/           тесты (включая настоящий Xray)
```

Ядро [Xray-core](https://github.com/XTLS/Xray-core) распространяется по лицензии MPL-2.0,
её текст лежит рядом с ядром в установленном приложении.
